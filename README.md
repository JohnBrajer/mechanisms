## Core principle

Everything that exists can be analyzed as mechanisms structured to function within larger mechanisms, recursively across arbitrarily large scales.

The analysis method is:

1. identify the underlying mechanisms,
2. analyze how each mechanism operates within its own analyzable region,
3. identify inputs, outputs, constraints, state changes, feedback, and dependencies,
4. analyze how those mechanisms interact,
5. analyze the behavior of the larger mechanism produced by those interactions,
6. repeat at the next relevant scale.

## Why it matters

Labels are often less decision-useful than function.

Two things can share a label while playing different causal roles. Two differently named things can perform the same decision-relevant function.

Mechanism-first analysis therefore asks:

> What is this doing, what changes its behavior, what does it change, and what larger system is it helping produce?

## Minimal representation

```
state -> mechanism -> state change
             |
             v
     larger mechanism
```

## Use cases

- software architecture
- organizations
- cognition
- institutions
- economic systems
- media systems
- biological analogies
- agent architectures
- creative systems

## Boundary

This is an analytical framework. It does not imply that every domain shares the same implementation or that analogy is proof of identity.
